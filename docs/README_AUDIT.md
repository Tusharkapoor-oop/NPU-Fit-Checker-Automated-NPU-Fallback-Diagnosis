## TASK 2 — Schema Reconciliation

### Schema used by the real profile JSONs

Both `experiments/baseline_fp32/profile.json` and
`experiments/optimized_int8/profile.json` share the **identical top-level schema**:

```
{
  "execution_summary": {
    "estimated_inference_time":        int  (µs)
    "estimated_inference_peak_memory": int  (bytes)
    "first_load_time":                 int  (µs)
    "first_load_peak_memory":          int  (bytes)
    "warm_load_time":                  int  (µs)
    "warm_load_peak_memory":           int  (bytes)
    "all_inference_times":             list[int]
    ...
  },
  "execution_detail": [
    {
      "name":             str
      "type":             str   (e.g. "Conv", "Clip", "QuantizeLinear")
      "compute_unit":     str   ("NPU" | "CPU" | "GPU")
      "execution_time":   int   (µs)
      "execution_cycles": int
    },
    ...
  ]
}
```

### `check_demo.py` / `experiments/demo_profile.json` discrepancy

`check_demo.py` reads flat keys (`name`, `type`, `compute_unit`,
`execution_time`, `inference_time`, `device`, `model_name`, `job_id`).
`experiments/demo_profile.json` uses this flat schema — it is a **separate
synthetic/exploratory file** and is NOT the same as the real AI Hub profiles.

**Conclusion**: The parser (`fitchecker/profile_parser.py`) is correctly
implemented against the real AI Hub schema (`execution_summary` /
`execution_detail`). `demo_profile.json` and `check_demo.py` are leftover
exploratory artefacts and do not affect the production pipeline.
